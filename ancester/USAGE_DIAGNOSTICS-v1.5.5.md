## 最小限の実機確認

1. Tampermonkeyで既存の「ChatGPT Response Favicon」を開き、コード全体を`chatgpt-response-favicon-v1.5.5.user.js`または`.user.txt`の内容へ置き換えて保存する。変更している場合は冒頭の`STALL_MINUTES`の値を引き継ぐ。
2. 未送信の文章を保存したうえで、確認対象の使用状況タブを再読み込みする。Alt + Shift + Uで`version: "1.5.5"`を確認し、診断を閉じる。
3. PCとChromeを起動したまま別タブへ移り、90秒ほど待つ。Chromeの「常にアクティブにするサイト」等の設定は、そのままでよい。
4. 使用状況タブへ戻り、Alt + Shift + UのJSONを全文コピーして報告する。待機中にPCがスリープした場合は、そのことだけ添える。

最初から利用枠が残っている場合は回復通知が出なくて正常。上限を意図的に使い切る必要はない。これは非表示中の監視・更新経路の採取であり、実際の制限解除通知の合格判定は別途行う。

期待する採取結果は、版番号1.5.5、`usageTrace.lastHiddenObservation`の非表示時の記録、`usageTrace.events`の時系列。記録がない・保存不可の場合も、そのJSONが診断材料になる。

## 診断追加の仕様

- `usageTrace`は、このタブのsessionStorageに保存する。最大48イベントに加え、最後の非表示観測・最新と最大の監視空白を保持する。24時間以上前の記録は読戻し・出力・次の記録時に除外する。保存済みデータの物理削除を専用タイマーで行うものではない。
- 状態が変わったときと、既存の走査で約15秒経過を確認したときに記録する。新しい監視タイマー、権限、通信、確認送信を追加しない。監視が止まっている間は記録も増えない。
- 枠の分類・残量・状態・時刻・可視状態・更新抑止理由だけを保存する。会話本文、入力本文、実際のURL・会話ID、アカウント情報は履歴へ入れない。読戻し時も許可した項目・値だけを採用する。
- 記録の読み書き失敗は診断用の状態へ分離し、本体の`usageStorageOK`を変更しない。通知判定、同一回復の重複抑制、再読み込みの安全条件は維持する。
- `@name`、`@namespace`、既存の設定・保存キーは変更しない。追加キーは`chatgpt-response-favicon:usage-trace:v1`のみ。

| 項目 | 意味・読み方 |
| --- | --- |
| lastHiddenObservation.reloadBlockedBy | 最後の非表示観測で自動更新を抑止した理由。nullはその観測で抑止条件に該当しなかったこと |
| routeKind | usage-path=使用状況専用パス、usage-hash=会話以外のハッシュ形式、conversation-usage=会話URL上の使用状況、conversation=会話、other=その他 |
| snapshotAt | その記録で参照した利用枠の最終走査時刻。イベント時刻と分けて鮮度を判断する |
| reload-request | 既存の条件を通過し、location.reloadを呼ぶ直前の記録。読み込み完了の証拠にはしない |
| runStartedAt／navigationType | スクリプト実行開始時刻とブラウザが提供する遷移の分類。再読み込み要求後の別の実行開始が記録されたかを照合する |
| lastGap／largestGap | 使用状況に関係する2分超または負方向の時計間隔。前後の画面分類・可視状態・壁時計と単調時計の差分を記録 |
| observationClock | 現在の実行中の監視間隔。会話画面での間隔も含むため、usageTrace内の間隔と分ける |
| recovery-result | 回復通知の調整処理が返った時点。requestedもOS通知表示の実測ではない |
| readStatus／writeStatus | 診断履歴専用の読込・保存状態。本体の保存状態とは別 |

`conversation-route`なら会話の保護で更新を抑止していたこと、`unsent-input`なら未送信内容を保護していたことを確認できる。`visible`は閲覧中という意味。長い空白にfreeze/resumeが併記されればイベント観測の証拠になるが、時計の差だけでPCスリープや停止原因を断定しない。

履歴は同じタブ内の再読み込みをまたぐ。ブラウザのセッション復元やタブ複製で保持範囲が変わる可能性があるため、全タブ共通のログや恒久保存としては扱わない。会話画面だけで使っている間は診断履歴を書き込まない。使用状況から離れた時点の記録の後は停止する。

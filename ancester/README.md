# ChatGPT Response Favicon 1.5.3

ChatGPT Response Notification開発中の、既存Tampermonkey版に対する修正版です。既存設定を引き継ぐため、スクリプトの`@name`、`@namespace`、設定キーは維持します。製品名・v0.1.0系列への移行はまだ実施していません。

## 更新

1. Tampermonkeyで既存の「ChatGPT Response Favicon」を開く。
2. コード全体を`chatgpt-response-favicon.user.js`で置き換えて保存する。`.user.txt`も同じ内容。
3. 未送信の入力を先に保存し、使用状況タブを含むChatGPTタブをすべて再読み込みする。
4. Alt + Shift + Dでバージョン`1.5.3`を確認する。旧版と新版を同時に有効にしない。

追加のTampermonkey権限はありません。通知だけでChromeを前面化しない設定は維持しています。無効化はTampermonkeyでこのスクリプトをOFFにします。1.5.2へ戻す場合は保存済みの旧コードへ戻してタブを再読み込みします。

## 今回の変更

- 利用上限の表示を一般エラーから分離。対応する回復表示を検出すると、回復通知と青いチェックで知らせます。
- 会話タブと使用状況タブの回復通知を共通の記録で調整し、同じ回復の通知をまとめます。
- 回復表示だけで作業再開・回答完了と判定しません。同じ停止状態のまま30分後に停滞通知を追加しません。実際に新しい進捗が出れば通常の監視へ戻ります。
- 警告後の再開通知が、5秒の待機中に消えてしまう1.5.2の不具合を修正しました。通常の進捗通知は引き続き出しません。
- 凍結・復帰・タイマーの大きな空白を診断できます。監視が2分超途切れた場合は、観測できなかった時間を停滞の証拠に使わず、連続観測時間を数え直します。
- 使用状況の自動再読み込みは、フォーカスのない入力欄にも未送信内容があれば止めます。会話URL上の設定画面も自動再読み込みしません。

## 通知とファビコン

| 状態 | 表示・通知 |
| --- | --- |
| 回答完了 | 緑のチェック。停止表示消失・結果更新等を確認し、約3秒安定してから通知 |
| 進捗が更新されず、連続観測が30分以上 | 黄色の警告。停止の疑いであり、サーバー停止を断定しない |
| 通信・生成エラーまたはオフライン | 赤い警告。対応表示が2秒以上続く場合 |
| 利用上限 | 青い警告。一般エラーや30分停滞と区別 |
| 利用枠の回復表示 | 青いチェック。回復通知はタブ間で調整 |
| 警告後の実際の進捗再開 | 再開通知。通常の作業更新だけでは通知しない |
| 承認・確認待ち | 対応表示を2秒以上確認した場合に通知。ボタンは押さない |

通常の会話通知は非表示タブが対象です。使用状況・利用枠回復の通知は表示中にも行います。タブへ戻るとアイコンを復帰します。待機を自分で確認した後は、その時点と同じ無変化に対する停滞通知を抑制し、新しい進捗で抑制を解除します。

## 利用枠の監視

使用状況タブ`https://chatgpt.com/settings/usage?tab=overview`を開いておきます。転送先の`#settings/Usage`も読み取り対象です。対応する5時間・週間・コードレビューの残量／使用率を読み取り、0%から正の残量、または明示的な制限から回復への変化を2秒以上確認します。最初から残量があるだけでは通知しません。

会話タブではUIの通知領域にある明示的な制限・回復の表示を使います。初期表示や本文・コード中の例、将来の回復予定、制限表示の消失だけでは回復としません。実際の表示文言が対応外の場合は検出できません。通信エラーが併記される場合は、そのエラーも通知します。

回復通知の調整は同じChromeプロファイル・同じ`chatgpt.com`の保存領域内で働きます。枠の分類と時刻だけをlocalStorageへ最大64件・8日分記録し、Web Locksで同時通知を防ぎます。タブを閉じても通知済み記録は残ります。別プロファイル・シークレットとの統合はしません。

枠名のない回復表示は、重複抑制を優先して関連する回復とまとめます。新しい制限を観測できないまま別の回復が起きた場合など、別事象もまとめられる可能性があります。すべてのモデル・枠の解除を保証する通知ではありません。アカウントを同じプロファイル内で切り替えた場合も記録は共通です。

Web Locksや共有記録を使用できない場合は回復デスクトップ通知を止め、診断に理由を表示します。会話タブの回復アイコンは使用できます。通知APIが失敗した場合は約1分後に再試行します。APIが受け付けた後のOS上の表示成否までは分かりません。

## 非アクティブ・折りたたみタブの制限

非表示でもスクリプトと画面更新が動いている場合は監視できます。使用状況ページは、安全条件を満たす場合だけ約60秒ごとに再読み込みします。読み取り不能・入力あり・会話URL・閲覧中・オフライン・保存失敗などの場合は停止します。

**凍結・破棄されたタブ、ブラウザ終了中、PCスリープ中は監視できません。折りたたみグループ内での即時通知と、回復後の通知遅延解消は未達です。** 1.5.2で「使用状況タブを開いたら回復通知が来た」原因は、報告だけでは凍結・間引き・画面更新停止のどれか確定できません。

当面は使用状況タブを折りたたみグループの外に置いてください。Chromeのメモリセーバー除外も候補ですが、グループ折りたたみやすべての凍結を防ぐ保証にはなりません。凍結中も扱うには拡張機能方式等の別設計を検討する必要があります。方式変更は未採用です。

## 待ち時間と診断

コード冒頭の利用者設定で変更できます。

```javascript
const STALL_MINUTES = 30;
```

`0.5`は30秒です。正の有限数を指定し、保存後に対象タブを再読み込みしてください。確認後は`30`へ戻します。これは監視側の警告時間であり、ChatGPTの処理や入力権を変更する設定ではありません。

| キー | 動作 |
| --- | --- |
| Alt + Shift + D | バージョン・状態・監視間隔等の診断 |
| Alt + Shift + U | 使用状況・共有通知・自動更新を止めている理由のJSON |
| Alt + Shift + N | 約5秒後のデスクトップ通知テスト |
| Alt + Shift + T / W / E | 約5秒後の完了／停滞／エラーアイコンのテスト |

診断の`lifecycle.freezeAt/resumeAt`はイベント観測時刻、`maximumGapMs`は監視間隔の最大値です。`wasDiscarded`は破棄後の再読み込みを示します。最大間隔だけで原因を凍結と断定しません。実際の最終進捗時刻と、監視再開後の連続観測時間は区別します。

テストキーは入力を送信しません。アイコンや通知経路の確認用で、ChatGPTの停止や回復を実際に起こすものではありません。無意味な重い依頼で停止を起こす方法は再現性を保証できません。状態遷移は同梱の模擬試験で確認し、実機では自然に起きた状態を記録します。`chrome://discards/`のFreezeは監視自体も止めるため、30分停滞の試験には適しません。

Tampermonkeyメニューで、デスクトップ通知・警告後の再開通知・利用枠回復・使用状況の自動更新を切り替えられます。初期値はON。OFF中の回復は後からまとめて再通知しません。

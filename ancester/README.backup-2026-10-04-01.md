# ChatGPT Response Favicon 1.5.0

別のタブを見ている間のChatGPTの変化を、ファビコンとデスクトップ通知で知らせるTampermonkey用スクリプトです。使用状況ページから、利用枠の回復も監視します。

## 更新・導入

1. Tampermonkeyで既存の「ChatGPT Response Favicon」を開きます。
2. コード全体を、この版の `chatgpt-response-favicon.user.js` に置き換えて保存します。以前追加した診断コードも置き換え対象です。テキスト版 `.user.txt` の中身も同一です。
3. 通知・設定保存などの追加権限についてTampermonkeyから確認が出たら、内容を確認して更新を許可します。
4. **開いているChatGPTタブを、使用状況タブも含めてすべて再読み込みします。**
5. Alt + Shift + Dでバージョンが `1.5.0` になっていることを確認します。
6. Alt + Shift + Nを押し、別タブへ移動します。約5秒後の「通知テスト」で、デスクトップ通知が表示されるか確認します。

旧版と新版を同時に有効にせず、動かすスクリプトは1本にしてください。保存だけでは開いているページの旧版は止まりません。

## 会話タブのデスクトップ通知

| 検出した変化 | 通知の扱い |
| --- | --- |
| 回答完了 | 完了を確認したときに通知 |
| 回答・作業表示の更新 | 初回は約5秒後、その後は同じ作業中に最大1分に1回 |
| 30分以上、進捗更新なし | 停滞警告を通知 |
| 継続するエラー・オフライン | エラー警告を通知 |
| 警告後の進捗再開 | 途中経過の通知として通知 |
| 承認・確認待ちの表示 | 対応する表示が2秒以上続いたら通知 |

送信・生成開始を検出した会話が対象です。別タブへ移動している間に通知します。表示中の会話、古い会話の読み込み、時計やアニメーションだけの更新では通知しません。短い回答は途中経過を省いて完了だけを通知することがあります。

通知本文にはタブのタイトルと状態を表示し、回答本文はコピーしません。通知をクリックすると元のタブへのフォーカスを試み、できない場合やタブの読み込み直し後は通知のURLを開きます。同じ会話の通知には同じタグを使います。

承認や再試行のボタンは自動では押しません。ChatGPT上の作業を再開させる機能ではありません。

## 利用上限の解除・利用枠の回復通知

`https://chatgpt.com/settings/usage?tab=overview` のタブを1つ開いたままにしてください。`#settings/Usage` へ転送された場合も対象です。

- 5時間などの時間枠、週間枠、コードレビュー枠の、対応する日本語・英語表示を読み取ります。
- 「残り0% → 0%より大きい値」「使用済み100% → 100%未満」、または明示的な制限中表示から回復表示への変化を確認して通知します。
- 初めてページを開いた時点で残量があるだけでは通知しません。まず制限中の状態を確認・記録する必要があります。
- 変化は2秒以上確認します。読み込み中、数値不明、表示の矛盾、リセット予定時刻の経過だけでは解除と判定しません。
- `25%` のように残量か使用率か分からない値は推測しません。数値付きのアクセシビリティ情報も、残量・使用率の意味が明示されている場合だけ使います。
- 複数の枠が同時に回復した場合は1件にまとめます。読み取れた別の枠がまだ制限中なら、そのことも通知に書きます。**一部の枠の回復は、すべてのモデルや機能が使えることを保証しません。**
- 使用状況の回復通知は、このタブを表示している場合にも出します。

使用状況タブが裏にある間は、表示更新のため約60秒ごとにそのタブを再読み込みします。閲覧中、入力欄にフォーカスがある状態、オフライン、状態保存に失敗した場合、読み取り可能な枠がない場合には自動再読み込みしません。会話タブは再読み込みしません。

制限中の記録はそのタブのsessionStorageに保存し、同じタブの再読み込みをまたいで使います。古い記録の有効期間は8日です。タブを閉じたり保存データを消したりすると、記録を引き継げない場合があります。複数の使用状況タブの間では重複通知を調整しません。

通知APIがエラーを返した場合は回復の記録を残し、約1分後に再試行します。APIが通知の依頼を受け付けても、OS側が実際に表示したかまでは判定できません。

## ON/OFF設定

Tampermonkeyのこのスクリプトのメニューから、次を個別に切り替えられます。初期値はすべてONです。

- デスクトップ通知
- 途中経過の通知
- 利用枠の回復通知
- 使用状況の自動更新

切り替え結果はダイアログに表示します。通知をOFFにしている間のイベントは後からまとめて通知しません。デスクトップ通知をOFFにしても、既存のファビコン通知は動作します。

## ファビコンと警告

| アイコン | 条件 |
| --- | --- |
| 緑のチェック | 回答完了を検出 |
| 黄色の警告 | 回答待機中、画面上の進捗更新を30分以上検出しない |
| 赤い警告 | 対応するエラー表示、またはオフライン状態が続き、2秒以上進捗がない |

タブへ戻ると元のアイコンに戻ります。何も依頼していないタブを30分放置しても警告しません。進捗が再開すれば停滞警告を解除し、正常完了を検出すると緑になります。エラー表示が消えただけで古い途中回答を完了扱いにはしません。

生成の停止操作や別の会話への移動では、その待機を解除します。停滞の時間を変更する場合は、コードの `const STALL_MINUTES = 30;` を変更し、保存後に再読み込みしてください。

## テストと診断

| キー | 動作 |
| --- | --- |
| Alt + Shift + N | 約5秒後にデスクトップ通知テスト |
| Alt + Shift + U | 利用枠の診断JSONを表示・コピー |
| Alt + Shift + D | バージョン、待機状態、通知処理などを表示 |
| Alt + Shift + T | 約5秒後に緑の完了アイコンをテスト |
| Alt + Shift + W | 約5秒後に黄色の停滞警告をテスト |
| Alt + Shift + E | 約5秒後に赤いエラー警告をテスト |

Tampermonkeyのメニューからも実行できます。アイコンのテストでは5秒以内に別タブへ移動してください。これらのテストは質問を送信せず、実際の完了・エラー・利用枠の回復を再現するものではありません。

通知テストが表示されない場合は、OS・ブラウザの通知設定と、おやすみモード／集中モードを確認してください。Alt + Shift + DのAPI表示がfalseなら、Tampermonkeyでこの版を保存し、ページを再読み込みしたか確認します。`requested` はAPIに通知を依頼した状態、`failed` はAPIエラー、`unavailable` はAPIを使用できない状態です。

使用状況ページでAlt + Shift + Uを押し、`status` が `recognized` か、`rows` に対象の利用枠が入るか確認できます。`unknown` の場合はその画面から回復を判定できません。表示されるJSONと、利用枠の見出し・数値の表示を共有すれば、画面に合わせて調整できます。診断内容は自動送信しません。

## 検証状況と範囲

構文チェックと、Node.js + jsdomでの92項目の模擬DOMテストに成功しました。詳細は `TESTING.md` と `tests/results.json` にあります。

以前の1.3.0では、実際のWork回答完了時にアイコンが変わったとのユーザー報告があります。Chatモードの修正と警告機能はその後の版から継承しています。**今回のデスクトップ通知と利用枠監視は、ユーザーの実ブラウザ・実際の使用状況表示では未確認です。** 接続先ブラウザがログアウト状態だったため、ログイン後のDOMを取得できていません。

閉じたタブは監視しません。タブの凍結・破棄、ブラウザやPCの終了、スリープ中は実行できず、タイマーの間引きで通知が遅れることがあります。読み取れないフレーム内や非表示の内部処理も対象外です。停滞通知は画面上の進捗を検出できないことを示し、サーバー側の停止を断定しません。ChatGPTの画面構造が変わると調整が必要です。

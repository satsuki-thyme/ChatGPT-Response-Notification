# 1.5.8：空欄フォーカスによる自動更新停止の修正候補

作成日: 2026-11-18 JST。通常配布の版番号なしソースは1.5.4を維持し、実機確認には版番号付き1.5.8を使う。

## 変更点

使用状況ページの外側にある空のtext入力にフォーカスが残っていても、文書全体にフォーカスがなければ、自動更新を継続できるようにした。タブやウィンドウを前面へ出したり、入力欄をblurしたりしない。

例外は独立した/settings/usageのoverviewだけ。値が厳密に空で、利用枠を認識でき、可視のmain/dialog外にあるtext入力に限定する。search/password/select/textarea等、範囲内の入力、会話に重なった設定画面には広げない。他の入力欄に内容があれば更新しない。空白文字だけの入力も保護する。

IMEの変換開始・終了とisComposingを観測し、変換中は更新を止める。これらは監視開始後に届いたイベントに基づく。実際のWindows IME、起動前の変換状態、別フレームや閉じたShadow DOMの内部を網羅した保証ではない。更新時は未送信入力を保存してページを再読み込みする。

## 導入と確認

1. Tampermonkeyで既存スクリプトをchatgpt-response-favicon-v1.5.8.user.jsまたは同内容の.user.txtへ入れ替える。有効な本体は1本にする。
2. 未送信入力を保存して、同じ使用状況ページを再読み込みする。利用枠が表示されたら別タブへ切り替え、約4分待つ。
3. 使用状況タブへ戻り、Alt + Shift + Uで開いた診断をCtrl+Cで全文コピーして提出する。選択が外れたら「全文を選択」を押す。

今回の確認対象は、自動更新が1回で止まらず2回以上続くこと。以前の履歴ではなく、scriptVersion=1.5.8とrunStartedAtを対応づけて判断する。更新要求だけで再読込成功とせず、pagehide・新実行・後続の認識も照合する。上限を使い切る操作や確認送信は不要。

## 診断の読み方

| 状態 | 期待する記録 |
| --- | --- |
| 独立した使用状況、hidden、空text入力が範囲外、文書フォーカスなし | 他の抑止がなければreloadBlockedBy=null、予定後にreload-request |
| 表示中 | visibleで更新を抑止 |
| 入力あり、空白文字だけの入力 | input-focusまたはunsent-inputで保護 |
| 観測中のIME変換 | inputComposition=true、他の優先理由がなければinput-composition |
| 利用枠を読み取れない | unrecognized。未知を解除扱いしない |

readerProbe.focus.hasContentは従来のtrim後の判定。hasRawContentは空白文字を含む内容の有無だけを示す。false/falseなら厳密な空欄、false/trueなら空白文字だけ。password/file/select等はnullのまま。入力の値、IMEのdata、本文、URLを記録・送信しない。従来の最大48件・24時間・同一タブの診断履歴と保存キーを維持する。

## 検証と未確認範囲

構文検査と合成185/185件合格（113＋16＋19＋7＋13＋17）。再現用コード・結果・原資料はZIP、説明はVERIFICATION.md。通知API、再読み込み、DOM、IMEイベントは模擬で、Windows通知表示の証拠ではない。

今回特定したフォーカスによる抑止を修正した。1.5.6で記録された長い未認識、実上限解除の通知到達、凍結・破棄・スリープ中の動作は未解決または未確認のまま。1.5.8で全要件完了とはしない。

## 戻す場合

既存スクリプトを1.5.7（前の診断候補）または1.5.4（通常配布）へ入れ替え、入力を保存して対象タブを再読み込みする。設定キーは共通で、旧版は追加診断項目を無視する。管理文書は新しい版を未使用名へ保全して元名を空けたうえで、同じ場所の.backup-2026-11-18-01ファイルを元名に戻せる。上書きや削除はしない。
